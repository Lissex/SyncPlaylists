# Расширение SyncPlaylists — материалы для магазинов

Черновик для Chrome Web Store (он же источник для Яндекс Браузера) и Firefox Add-ons (AMO).
Пишется по коду этапа 4c-2; перед публикацией (после 4c-3 — первой площадки) сверить с
актуальным манифестом (`extension/src/manifest.ts`) и формами магазинов.

## Single purpose

**RU.** Расширение выполняет перенос плейлистов и лайков между музыкальными площадками
(SoundCloud, Яндекс Музыка и др.) в браузере пользователя: по команде, которую пользователь
дал на сайте SyncPlaylists, оно читает его плейлисты на площадке-источнике, ищет треки и
создаёт плейлисты / ставит лайки на площадке-назначении от его имени, в его сессии.

**EN.** The extension transfers playlists and liked tracks between music services
(SoundCloud, Yandex Music, etc.) inside the user's browser: when the user starts a transfer on
the SyncPlaylists website, it reads the user's playlists on the source service, searches for
the tracks and creates playlists / likes tracks on the target service on the user's behalf, in
the user's own session.

Всё, что делает расширение, служит этой одной цели; рекламы, аналитики, изменения страниц
и других функций нет.

## Разрешения и обоснования

| Разрешение | Зачем | Почему без него нельзя |
|---|---|---|
| `storage` | Токен устройства (выдаётся при привязке к аккаунту SyncPlaylists), журнал выполненных записей (чтобы повтор не создал второй плейлист), неотправленные результаты, состояние для окна расширения. | Service worker останавливается браузером; без хранилища привязка и защита от дублей терялись бы. |
| `alarms` | Переподключение к серверу и опрос подтверждения привязки после остановки service worker; закрытие фоновой вкладки после простоя; очистка журнала через сутки. | Таймеры service worker не переживают его остановку. |
| `scripting` | Выполнение операции переноса в странице площадки (`scripting.executeScript`, `world: "MAIN"`): запрос к API площадки идёт из её же страницы, в сессии пользователя. | Это единственный способ сделать запрос от имени пользователя, не получая его cookie/токены. |
| host: сервер SyncPlaylists (`https://<api>/*`) | Привязка к аккаунту и WebSocket-канал задач. | Единственный сервер, с которым расширение обменивается данными. |
| optional host: `https://soundcloud.com/*` (4c-3; `https://music.yandex.ru/*` добавится с операциями Яндекса, 4c-4) | Фоновая вкладка площадки и выполнение в ней операций. | Запрашивается **только** по явному согласию пользователя на отдельном экране, для каждой площадки отдельно; отзывается выключателем в окне расширения. |

**Чего нет и почему:**
- `cookies` — API `cookies` не используется: запросы делает страница площадки сама. Яндекс
  (4c-4) — `fetch` с `credentials: "include"`. SoundCloud: сайт сам авторизует запросы к своему
  API заголовком из cookie сессии, и функция операции делает то же **внутри страницы**: значение
  не покидает страницу и не попадает ни в background, ни на сервер (тест «канарейка» в
  `extension/tests/no-secrets.test.ts`). Из того же cookie берётся только id аккаунта — чтобы
  сверить, что вошли в нужный аккаунт.
- `tabs` — не нужен: вкладки создаются и закрываются без чтения истории/адресов чужих вкладок
  (адрес своей фоновой вкладки виден благодаря host permission её сайта).
- `webRequest` / `declarativeNetRequest` — расширение не перехватывает и не меняет трафик.
- content scripts — ничего не внедряется в страницы, которые пользователь открывает сам.
- `<all_urls>` и широкие host-шаблоны — только конкретные сайты площадок.

## Remote code

**Нет.** Весь исполняемый код находится в пакете расширения. Сервер присылает только имя
операции из фиксированного реестра (`extension/src/background/registry.ts`) и данные
(аргументы), которые проходят строгую схему; неизвестная операция отклоняется. В страницу
передаются функция из пакета и аргументы — никаких `eval`, строк кода или скачиваемых
скриптов.

## Данные (Chrome Web Store: «Privacy practices»; AMO: `data_collection_permissions`)

- **Что передаётся на сервер SyncPlaylists:** содержимое сайтов площадок, нужное для переноса:
  названия, исполнители, длительность, ISRC и id треков; названия и id плейлистов (у
  приватного плейлиста SoundCloud — и секрет его ссылки); id и имя аккаунта на площадке.
  Ответы площадки обрезаются в странице до фиксированного набора полей. Категория CWS — *Website content*; AMO — `websiteContent`
  (обязательная).
- **Не передаётся никогда:** cookie, токены, пароли, заголовки авторизации площадок (проверяется
  тестом `extension/tests/no-secrets.test.ts`), история браузера, содержимое других сайтов.
- Данные используются только для выполнения переноса, не продаются и не передаются третьим
  лицам, не используются для рекламы и оценки кредитоспособности.
- Политика конфиденциальности: `docs/EXTENSION_PRIVACY.md` (опубликовать на сайте и указать URL
  в карточке).

Отметки CWS (Certify): не продаём данные; не используем/не передаём не для основной функции;
не используем для кредитоспособности/займов.

## Firefox (AMO)

- `browser_specific_settings.gecko.id` — задаётся `WXT_GECKO_ID` при сборке; для публикации
  выбрать постоянный id.
- `strict_min_version: 128.0` — `world: "MAIN"` в `scripting.executeScript`.
- `data_collection_permissions: { required: ["websiteContent"] }` — встроенное согласие Firefox.
- Код собирается и минифицируется WXT/Vite → AMO требует исходники: `pnpm zip:firefox`
  кладёт рядом с пакетом архив исходников и инструкцию сборки (`pnpm install && pnpm
  build:firefox`, Node 24, pnpm 10+).

## Яндекс Браузер

Отдельной публикации нет: Яндекс Браузер ставит расширения из Chrome Web Store (и из
каталога Opera Add-ons). Сборка та же, что для Chrome (`chrome-mv3`). Origin расширения —
`chrome-extension://<id из Chrome Web Store>`; этот id добавляется в
`EXTENSION__ALLOWED_EXTENSION_IDS` сервера.
